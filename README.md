# B232270029, З.Анхбаяр

### Туршилтын тохиргоо

- **Node version:** v24.21.0
- **Newman version:** v6.2.2

## API-ийн бодит ажиллагаа

Энэ спецификаци нь өгсөн `server.js`-ийн хэрэгжүүлэлтэд үндэслэв. Тестлэгдэх endpoint: `POST /registrations`.

- Бүртгүүлэх хүсэлт зөвхөн `studentID`, `courseID` талбар шаарддаг.
- `coursesTaken` нь `PUT /students/:id` setup хүсэлтээр хадгалагдана. Setup-д энэ талбарыг орхивол `[]` болно; үүнээс болж `400` буцаахгүй.
- Хичээлийн `prerequisites` нь `PUT /courses/:id`-аар хадгалагдана. Орхивол `[]` болно.
- Амжилт: HTTP `201`, `result: "OK"`, шинээр үүссэн `registrationID`.
- Бизнесийн дөрвөн алдаа: HTTP `200` ба харгалзах `ERROR_*`.
- `studentID` эсвэл `courseID` дутуу буюу falsy утгатай бол HTTP `400`, `ERROR_BAD_REQUEST`.
- Шалгалтын дараалал: JSON задлах → шаардлагатай ID-ууд → оюутан байгаа эсэх → `status === "active"` → хичээл байгаа эсэх → урьдач нөхцөл. Эхний илэрсэн алдааг буцаана.
- JSON буруу бүтэцтэй бол HTTP `400`, `ERROR_BAD_JSON` (доорх үндсэн 12 спецификациас тусдаа).

## 1. Сонголтууд

| Шалгах шинж                             | Сонголт          | Тайлбар / ангилал                                             |
| --------------------------------------- | ---------------- | ------------------------------------------------------------- |
| `studentID`-гийн хүчинтэй байдал        | Идэвхтэй         | Оюутан бүртгэлтэй, хичээл сонгох эрхтэй                       |
| `studentID`-гийн хүчинтэй байдал        | Идэвхгүй         | Оюутан бүртгэлтэй боловч идэвхгүй — алдааны анги              |
| `studentID`-гийн хүчинтэй байдал        | Байхгүй          | Тухайн ID-тай оюутан бүртгэлгүй — алдааны анги                |
| Оюутны үзсэн хичээлүүд (`coursesTaken`) | Урьдач хангана   | Шаардлагатай бүх хичээлийг үзсэн                              |
| Оюутны үзсэн хичээлүүд (`coursesTaken`) | Урьдач хангахгүй | Шаардлагатай хичээлээс дор хаяж нэгийг үзээгүй — алдааны анги |
| `courseID`-гийн хүчинтэй байдал         | Байгаа           | Сонгох хичээл бүртгэлтэй                                      |
| `courseID`-гийн хүчинтэй байдал         | Байхгүй          | Сонгох хичээл бүртгэлгүй — алдааны анги                       |
| Хичээлийн урьдач нөхцөл                 | Бүгд үзсэн       | Урьдач хичээлүүд бүгд `coursesTaken`-д байна                  |
| Хичээлийн урьдач нөхцөл                 | Огт үзээгүй      | Урьдач хичээлүүдээс нэг ч хичээл үзээгүй                      |
| Хичээлийн урьдач нөхцөл                 | Зарим нь         | Урьдач хичээлүүдээс заримыг үзсэн ч бүгдийг үзээгүй           |

**Хамаарал:** “Урьдач хангана” болон “Бүгд үзсэн” нь нэг нөхцөлийн хоёр илэрхийлэл. “Огт үзээгүй”, “Зарим нь” нь хоёулаа “Урьдач хангахгүй” ангилалд орно. Иймээс эдгээрийг үл хамаарах сонголт мэт бүх боломжит хослолоор үржүүлэхгүй. Урьдач нөхцөлгүй хичээлд хоосон `coursesTaken` байсан ч урьдач хангана. Байхгүй оюутан/хичээлд хамаарах үнэлгээг `—` гэж тэмдэглэв.

## 2. Тестийн өгөгдөл

Доорх ID-ууд нь жишээ тестийн өгөгдөл; бодит бүртгэлийн ID биш. Тест бүрийг тусдаа, цэвэр төлөвөөс ажиллуулна.

| ID     | Төлөв / утга                            |
| ------ | --------------------------------------- |
| `S001` | Идэвхтэй оюутан                         |
| `S002` | Идэвхгүй оюутан                         |
| `S999` | Бүртгэлгүй оюутны ID                    |
| `C201` | Байгаа хичээл; урьдач нь `[C101, C102]` |
| `C100` | Байгаа хичээл; урьдач нөхцөлгүй `[]`    |
| `C999` | Бүртгэлгүй хичээлийн ID                 |
| `C050` | Урьдач нөхцөлд ороогүй өөр хичээл       |

## 3. Спецификациуд

Нэг мөр = нэг тестийн жор. `—` нь тухайн шалгалт хамаарахгүй эсвэл өмнөх алдаанаас шалтгаалан үнэлэгдэхгүй гэсэн утгатай. HTTP статус болон `result`-ийг тус тусад нь шалгана; HTTP `200` нь энэ гэрээний хувьд бизнесийн амжилт гэсэн үг биш.

### Initialization ба хүсэлт

Тест бүрийн өмнө серверийг зогсоож `node server.js` гэж дахин ажиллуулна. Ингэснээр in-memory өгөгдөл цэвэрлэгдэж, амжилттай тестийн `registrationID` бүр `1` байна. Бүх хүсэлтийн JSON талбарын нэр, string утгыг давхар хашилтаар бичнэ.

Эхлээд тест бүрд дараах хоёр setup хүсэлтийг илгээнэ (тус бүр `200`, `{"result":"OK"}`):

```http
PUT /courses/C201
Content-Type: application/json

{"prerequisites":["C101","C102"]}
```

```http
PUT /courses/C100
Content-Type: application/json

{"prerequisites":[]}
```

Дараа нь доорх мөрийн оюутны setup-ийг хийж, үндсэн хүсэлтийг илгээнэ. `S999`, `C999`-ийг setup-аар үүсгэхгүй. `C101`, `C102`-ийг тусдаа хичээл болгон үүсгэх шаардлагагүй: код зөвхөн ID нь `coursesTaken` жагсаалтад байгаа эсэхийг шалгадаг.

| Тест | Оюутны setup endpoint | Setup JSON body                                        | `POST /registrations` JSON body          |
| ---- | --------------------- | ------------------------------------------------------ | ---------------------------------------- |

| SP02 | `PUT /students/S001`  | `{"status":"active","coursesTaken":["C050"]}`          | `{"studentID":"S001","courseID":"C201"}` |

### Нэмэлт үр дүнгийн шалгалт

| Тест       | Бүрэн хариу JSON                                             |
| ---------- | ------------------------------------------------------------ |
| SP01, SP08 | `{"result":"OK","registrationID":1}`                         |
| SP02, SP09 | `{"result":"ERROR_PREREQUISITES","missing":["C101","C102"]}` |
| SP03       | `{"result":"ERROR_NO_COURSE"}`                               |
| SP04, SP07 | `{"result":"ERROR_INACTIVE_STUDENT"}`                        |
| SP05, SP06 | `{"result":"ERROR_NO_STUDENT"}`                              |
| SP10, SP12 | `{"result":"ERROR_BAD_REQUEST"}`                             |
| SP11       | `{"result":"ERROR_PREREQUISITES","missing":["C102"]}`        |

Үндсэн хүсэлтийн дараа `GET /registrations` нь HTTP `200` буцаана. SP01-д `[{"registrationID":1,"studentID":"S001","courseID":"C201"}]`, SP08-д `[{"registrationID":1,"studentID":"S001","courseID":"C100"}]`, бусад тестэд `[]` байх ёстой. Энэ нь алдаатай хүсэлт бүртгэл үүсгээгүйг шалгана.
